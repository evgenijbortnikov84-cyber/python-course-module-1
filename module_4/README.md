# Модуль 4. Исправления после проверки

## Бинарный поиск

`binary_search(numbers, target)` принимает список по возрастанию. Порядок заранее обеспечивает вызывающий код. При повторах возвращается любое найденное вхождение, при отсутствии цели -1.

Лучший случай O(1), худший O(log n), память O(1). Для миллиона элементов достаточно не более 20 проверок середины, поскольку 2²⁰ = 1 048 576.

## Сортировка вставками

`insertion_sort(numbers)` меняет исходный список и возвращает None. Сортировка по возрастанию, без параметров key и reverse.

Стабильность обеспечивается строгим сравнением >. Равные элементы не перемещаются друг через друга. На отсортированном списке время O(n), на случайном порядке различных значений в среднем O(n²), на обратном порядке O(n²). В худшем случае выполняется n(n - 1)/2 сдвигов. Дополнительная память O(1).

```python
numbers = [5, -2, 5, 1]
insertion_sort(numbers)
print(numbers)
```

## Поиск в ширину

- `breadth_first_search(graph, start)` возвращает только порядок обхода. Хранит очередь, посещённые вершины и результат; не рассчитывает расстояния и предшественников.
- `breadth_first_search_details(graph, start)` возвращает порядок, расстояния и предшественников.
- `shortest_path(graph, start, target)` использует отдельный BFS с предшественниками и прекращает поиск сразу при обнаружении цели. Полный порядок и расстояния не вычисляются.

Граф задаётся словарём со списками соседей. Вершины хешируемые; могут находиться только среди соседей. Граф не должен меняться во время обхода, списки соседей должны допускать повторный просмотр.

### Проверка вершин и результат

| Случай | Результат |
| --- | --- |
| Начало отсутствует | ValueError во всех трёх функциях |
| Цель отсутствует | ValueError в shortest_path |
| Цель существует, но недостижима из начала | None |
| Начало равно существующей цели | [start] |
| Путь существует | Список вершин от начала до цели включительно |

Проверка сначала ищет вершину среди ключей словаря, в среднем O(1). Если ключа нет, просматривает соседей до первого совпадения, не создавая множество всех вершин. В худшем случае эта проверка требует O(V + E) времени, но O(1) дополнительной памяти. При сохранении вершин только среди соседей полностью исключить такой просмотр нельзя. Альтернатива: заранее требовать отдельный ключ для каждой вершины или подготовить индекс вершин.

Проверка существования цели отложена до неуспешного завершения поиска. Найденная при обходе цель уже заведомо существует. Поэтому поиск близкой достижимой цели не просматривает недостижимые части графа, если start является ключом.

### Несколько кратчайших путей

BFS возвращает первый найденный кратчайший путь по числу рёбер. Выбор зависит от порядка соседей в списках и очереди, а не от алфавита или порядка ключей словаря.

Например, для A: [B, C], B: [D], C: [D] получается [A, B, D]. Если изменить список A на [C, B], получится [A, C, D]. Оба пути имеют два ребра. Для воспроизводимости используйте списки с фиксированным порядком; множества соседей такого порядка не гарантируют.

Очередь deque извлекает начало за O(1). Отметка при добавлении исключает повторную постановку вершины. Для обхода достижимой части время O(Vr + Er), память O(Vr), где Vr и Er относятся к достижимым вершинам и рёбрам. Поиск пути может завершиться раньше. С учётом проверки вершин без ключа общая худшая оценка остаётся O(V + E), память O(V). Удаление лишних словарей уменьшает расход памяти, но не меняет её порядок роста.
