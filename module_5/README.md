## StringVar и Point

StringVar вызывает set из конструктора, чтобы проверка типа была в одном месте. Некорректное значение не меняет прежнюю строку.

Point сравнивает координаты через __eq__; для другого типа возвращает NotImplemented. Координаты изменяются методом move. Поэтому __hash__ = None указан явно: set([Point(1, 2)]) и {Point(1, 2): "значение"} вызывают TypeError.

Это не ошибка, которую следует исправлять хешем по изменяемым координатам. Равные объекты должны иметь равные хеши, а хеш ключа не должен меняться, пока он находится в словаре или множестве. object.__hash__ нарушил бы первое правило, hash((x, y)) после move нарушил бы второе. Для ключа можно сохранить отдельный неизменяемый снимок: (point.x, point.y). Изменение точки не изменит этот кортеж. Другой возможный дизайн: неизменяемая точка, у которой перемещение создаёт новый объект; здесь сохранено поведение исходного задания.

## Warrior и ArenaWarrior

Оба класса имеют один и тот же интерфейс:

- attack(opponent) готовит удар и передаёт его opponent.receive_attack(...). В ArenaWarrior этот метод не переопределяется.
- prepare_attack() возвращает Attack: одну силу удара и признак истощения атакующего. Никаких значений защиты или потери брони в Attack нет.
- receive_attack(attack) получает только Attack. Базовый класс передаёт силу в take_damage. Наследник сначала учитывает собственную защиту и броню.
- take_damage(amount) получает только целое неотрицательное число готового урона и уменьшает здоровье. Он одинаков у обоих классов. Это низкоуровневая операция, она намеренно не рассчитывает защиту.

Атакующий определяет только свою силу и расход выносливости. Получатель самостоятельно решает, как обработать удар. Для уклонения достаточно переопределить receive_attack в новом наследнике. Тест DodgingWarrior возвращает нулевой урон; атакующего и арену менять не требуется.

Раньше Hit содержал три заранее брошенных числа, чтобы применение удара не требовало новых бросков. Это связывало атакующего с устройством защиты и расходовало случайные числа для неиспользуемых вариантов. Hit и prepare_hit удалены. Атакующий теперь делает один бросок, а получатель бросает потерю брони только при действующей защите с бронёй. При том же seed последовательность новой версии может отличаться от прежней; повторные запуски новой версии с одинаковым seed воспроизводимы.

### Правила боя

Начальные здоровье, броня и выносливость равны 100. Атака расходует 10 выносливости. При ненулевой выносливости до удара сила равномерно выбирается из 10..30. Защищающийся получатель с бронёй вычитает 10, получая прежний равномерный диапазон 0..20, и теряет 0..10 брони. При истощении атакующего сила 0..10, защита не уменьшает этот диапазон, но броня всё равно расходуется. Все показатели ограничены снизу нулём.

Arena принимает ровно двух разных ArenaWarrior, как в исходном задании. Это явное ограничение конструктора, не универсальная арена для произвольного числа участников. Схема 1 - index убрана; пары участников заданы явно. Расширение на троих потребует новых правил выбора цели и определения результата.

Действия выбираются случайно до нанесения ударов. Arena вызывает attack у каждого выбравшего атаку, даже если он уже получил поражающий удар в этом раунде. В текущих классах сила не зависит от здоровья, поэтому обе атаки выполняются согласно выбранным действиям. Для будущего наследника, чья сила зависит от здоровья, этого условия недостаточно: понадобится отдельный снимок состояния раунда. Такая поддержка здесь не заявляется.

Порог поражения 10 или меньше взят из задания. Если проиграли оба, результат ничейный. Помилование выполняется после партии, сохраняет оставшееся здоровье или оставляет 1 при нуле. play имеет лимит раундов, чтобы постоянная защита не приводила к бесконечному циклу. Для новой партии создаются новые участники и Arena.

### Источник случайности

RandomProvider объявлен через typing.Protocol с методами choose_action() -> str и roll_damage(bounds) -> int. RandomSource является обычной реализацией с отдельным random.Random(seed). Один источник передаётся в Arena и её участников; отдельному воину его можно передать в конструктор.

При создании проверяются наличие и вызываемость методов. Действия, диапазоны и типы возвращаемого урона проверяются в месте использования. runtime_checkable не проверяет сигнатуры и типы возвращаемых значений полностью; Protocol описывает их для статического анализатора. Объект с неверной сигнатурой всё ещё может вызвать TypeError при вызове. Не заявляется полная проверка произвольного объекта в рантайме.

## Model и Article

Модели объявляются через dataclass. Имя, тип и значение по умолчанию находятся в одной строке, например title: str = "Заголовок". Отдельного словаря fields больше нет. Сериализация получает объявления через dataclasses.fields, включая унаследованные поля; произвольные свойства не перебираются.

Проверка строгая: type(value) is field.type. Поэтому bool не принимается вместо int. Учебная реализация поддерживает конкретные типы в аннотациях, не Union, строковые аннотации или проверку элементов вложенных коллекций. Подкласс с новыми полями также нужно пометить @dataclass. Типы проверяются при save/load, а не при обычном присваивании атрибута.

save возвращает None. load проверяет точный набор полей и типы, затем создаёт объект через cls(**values). Старые JSON-файлы Article с title, text и author читаются без изменения формата.

Новый временный файл создаётся через open(..., "x") со случайным именем в том же каталоге. На POSIX права соответствуют обычному open: 0666 с учётом umask. При umask 022 получится 0644, при umask 077 получится 0600. Принудительное расширение прав до 0644 не выполняется. При замене существующего файла сохраняются прежние биты прав. На Windows действуют ACL каталога; отдельное копирование ACL и владельца не реализовано.

После успешной записи и закрытия временный файл заменяет целевой. При ошибке созданный временный файл удаляется. Режим x защищает от перезаписи файла при совпадении случайного имени; такой чужой файл не удаляется в finally. Ошибка сериализации также не повреждает исходный файл. Защита от одновременных правок разных процессов и гарантия сохранности при отключении питания не заявляются.
