## Часть 1

- [Вклад](part_1/level_1.py): ввод суммы, цели и ставки на трёх строках. Функция years_to_target возвращает только int. Недостижимая цель вызывает ValueError. Если расчёт не завершился за MAX_YEARS = 10 000, возникает RuntimeError с отдельным сообщением. Это ограничение длительности расчёта, а не утверждение, что цель никогда не будет достигнута. Лимит можно передать параметром max_years. Достижение цели ровно в последний разрешённый год считается успехом.
- Decimal и ежегодное округление вниз до копеек сохранены как явно выбранное учебное допущение. Банковские правила могут быть другими. Формула с логарифмом не используется, поскольку она не учитывает это ежегодное округление.
- [Цикл while](part_1/level_2.py): ноль допустим и ничего не выводит. Ошибка только при отрицательном количестве или неверном типе.
- [Сумма цифр](part_1/level_3.py): знак минуса не считается цифрой; divmod получает частное и остаток. Например, -507 даёт 12.

## Часть 2

JSON-ввод удалён. У каждого файла есть короткий пример данных, который можно изменить непосредственно в коде. Функции по-прежнему принимают другие данные и проверяются отдельно.

- [Повторения](part_2/level_1.py): словарь считает элементы по ключу (type(item), item). Поэтому 1, True, 1.0 и "1" различаются. Обход исходных данных один, затем просмотр счётчиков. Среднее время O(n), память O(k). Поддерживаются хешируемые элементы; вложенные списки не поддерживаются. Порядок результата совпадает с первым появлением элементов.
- [Максимум матрицы](part_2/level_2.py): пустая матрица и пустая строка отклоняются. Значения должны быть конечными числами. Генератор внутри max не создаёт промежуточный список максимумов строк.
- [Имена и id](part_2/level_3.py): основной пример использует список пар, а не словарь: [("Анна", 1), ("Иван", 1), ("Анна", 2)]. Ни одна пара не теряется. Числовые id допускаются. Можно передать и готовый словарь, но уже потерянные при его создании повторные ключи восстановить нельзя. Идентификаторы должны быть хешируемыми; для них сохраняется обычное равенство Python, поэтому используйте единый тип id.

## Часть 3

- [Площадь треугольника](part_3/level_1.py): три положительные конечные стороны, сумма двух меньших строго больше третьей. Ошибки ввода перехватываются. На почти вырожденных треугольниках формула Герона может терять точность float.
- [Короткие слова](part_3/level_2.py): восстановлен многострочный ввод через sys.stdin.read(). Перед вводом указано завершение: Windows - Ctrl+Z и Enter; Linux/macOS - Ctrl+D. Пустые строки внутри текста сохраняются. Можно перенаправить текстовый файл в stdin. Дефис и апостроф внутри слова не разделяют его на части. Порог строго меньше MAX_WORD_LENGTH = 5, знаки внутри слова входят в длину.
- [Максимальное число](part_3/level_3.py): непустой набор неотрицательных целых чисел; сортировка по сравнению двух склеек. Нули дают 0. Тест перебирает все перестановки небольших наборов; отдельная проверка сравнения покрывает тройки элементов. Доказательство приведено ниже, тест не заменяет его.

### Почему сравнение склеек транзитивно

Пусть a и b обозначают десятичные записи неотрицательных чисел A и B, а m и n обозначают длины записей. Записи непустые, поэтому знаменатели ниже положительны.

```text
ab >= ba
A * 10^n + B >= B * 10^m + A
A * (10^n - 1) >= B * (10^m - 1)
A / (10^m - 1) >= B / (10^n - 1)
```

Таким образом, каждой записи соответствует одно рациональное число A / (10^m - 1). Сравнение склеек эквивалентно сравнению этих чисел. Их порядок транзитивен: если значение для a не меньше значения для b, а для b не меньше значения для c, то значение для a не меньше значения для c. Равные значения образуют согласованные группы равенства.

В коде дроби вычислять не нужно: используются строки и точное сравнение склеек. Обмен неправильно упорядоченных соседей не уменьшает итоговое число: длина фрагмента и остальная запись остаются прежними. Последовательно устранив такие пары, получаем максимальный результат.

## Часть 4

[accounts.py](part_4/accounts.py) остаётся локальной учебной программой для одного запущенного экземпляра. Одновременная регистрация из нескольких процессов не поддерживается. Избыточный фиктивный расчёт хеша для отсутствующего аккаунта удалён. Программа не обещает скрывать существование логина или выравнивать время входа: ответ «Логин занят» намеренно оставлен как часть задания.

Хранилище не изменено: `~/.python_course_accounts`, обычно `C:\Users\Windows\.python_course_accounts`. Для тестов параметр directory направляет данные во временную папку. Реальные аккаунты тестами не изменяются.

- Новая запись содержит version = 2 и iterations. Вход использует число из записи, а не текущую константу ITERATIONS. Для старого формата без обоих полей используется отдельная неизменяемая константа LEGACY_ITERATIONS = 600 000.
- Неизвестная версия и недопустимое число итераций отклоняются. Допустимый диапазон записи: 1..2 000 000. Для новых регистраций оставлено 600 000. Это не рекомендация по настройке промышленной системы.
- Пустой каталог не считается занятым логином. После неудачной записи можно повторить регистрацию. Готовый файл сначала записывается во временный, затем публикуется заменой; временный файл удаляется при ошибке. Повреждённый существующий account.json автоматически не перезаписывается.
- Логин нормализуется в NFC. Например, «ё» и «е + комбинируемое двоеточие» становятся одинаковой записью. NFC не объединяет все визуально похожие символы: латинская a и кириллическая а остаются разными. Регистр учитывается; длина от 1 до 64 символов, пробелы по краям запрещены.
- Старые записи ищутся также по нормализованному логину внутри JSON. Их файлы не меняются. Если несколько старых аккаунтов совпали после нормализации, регистрация сообщает о конфликте, вход отклоняется; автоматического объединения нет. Для небольшой учебной базы допустим линейный просмотр файлов.
- Новый пароль содержит от 8 до 128 символов и не состоит из пробелов. Верхняя граница действует и при входе, до вычисления хеша. Старые короткие пароли допускаются при входе; старые пароли длиннее 128 символов не поддерживаются этой версией. Пароли не нормализуются.
- Логин хранится открыто. SHA-256 в имени каталога нужен для безопасного имени пути, а не для сокрытия личности. Пароль открыто не хранится: используются соль и PBKDF2. Соль не является секретом. Сравнение хешей выполняется через compare_digest.

Версионирование и чтение старых записей сохранены, чтобы исправление не потребовало удаления предыдущих аккаунтов. Дополнительной инфраструктуры сервера, блокировок и автоматической миграции нет.
