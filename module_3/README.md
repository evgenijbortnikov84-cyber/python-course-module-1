## Запуск и проверка

Запускайте программы из корня репозитория, например:

```console
python module_3/part_1/level_1.py
python module_3/part_2/level_3.py
python module_3/part_4/accounts.py
python module_3/lesson_3/shopping_list.py
python -B -m unittest discover -s tests -p test_module_3.py -v
python -B -m unittest discover -s tests -p test_shopping_list.py -v
python -B -m unittest discover -s tests -v
```

Дополнительные библиотеки не нужны. [Ожидаемые результаты](EXPECTED_OUTPUT.md), [отчёт общего запуска](TEST_RESULTS.txt), [журнал исправлений](AUDIT.md).

## Часть 1. Циклы и числа

| Уровень | Файл | Изменения |
| --- | --- | --- |
| 1. Вклад | [level_1.py](part_1/level_1.py) | Расчёт выделен в years_to_target. Неверный ввод, NaN и бесконечность отклоняются. Недостижимая цель возвращает None. |
| 2. while | [level_2.py](part_1/level_2.py) | repeat_message проверяет положительное целое число. Для нуля, отрицательного и нечислового ввода выводится сообщение. |
| 3. Сумма цифр | [level_3.py](part_1/level_3.py) | digit_sum обрабатывает ноль и отрицательные целые числа. Некорректный ввод не вызывает traceback. |

Вклад: вводите начальную сумму, цель и годовую ставку на трёх строках. Сохранено допущение предыдущей версии: ежегодное округление вниз до копеек. Это правило учебной модели, не универсальное правило банков. Decimal используется для десятичных расчётов, ROUND_FLOOR задаёт округление, quantize оставляет две цифры после точки. Если цель уже достигнута, ответ 0. Если вклад не увеличивается, цель недостижима. Конструкция while ... else заменена обычным возвратом результата после цикла.

Сумма цифр: знак минуса не считается цифрой. abs берёт модуль, divmod одновременно выдаёт частное и остаток от деления на 10. Например, для -507 результат 12.

## Часть 2. Коллекции

| Уровень | Файл | Изменения |
| --- | --- | --- |
| 1. Повторения | [level_1.py](part_2/level_1.py) | Counter считает элементы за один проход. Затем отбираются элементы с количеством больше одного. |
| 2. Максимум матрицы | [level_2.py](part_2/level_2.py) | matrix_max проверяет пустую матрицу, пустые строки и числовые значения. |
| 3. Ключи и значения | [level_3.py](part_2/level_3.py) | group_names_by_id хранит список имён для каждого id. Совпадающие id не уничтожают данные. |

Вместо зашитых данных программы читают одну строку JSON. Строки в JSON заключаются в двойные кавычки. Примеры:

```text
[1, 4, 1, "hello", "hello"]
[[9, 70], [100, 1]]
{"Анна": "id1", "Иван": "id1"}
```

Counter рассчитан на хешируемые элементы, например числа и строки. Вложенные списки не поддерживаются и вызывают понятное сообщение. Итоговый порядок совпадает с порядком первого появления повторяющихся элементов. Среднее время O(n), дополнительная память O(k), где k обозначает число разных элементов.

Максимум: пустые строки отклоняются, а не пропускаются. Строки разной длины допустимы. Генератор внутри max выдаёт максимумы строк по одному; промежуточный список не создаётся.

При группировке даже единственному имени соответствует список: {'id1': ['Анна']}. Интерфейс функции принимает словарь, а консольный ввод требует строковые id. Имена как ключи входного словаря должны быть уникальными.

## Часть 3. Функции

| Уровень | Файл | Изменения |
| --- | --- | --- |
| 1. Площадь | [level_1.py](part_3/level_1.py) | Ввод ровно трёх сторон, проверка конечности чисел, перехват ошибок ввода и вычисления. |
| 2. Короткие слова | [level_2.py](part_3/level_2.py) | MAX_WORD_LENGTH = 5; слова с внутренним дефисом и апострофом не разделяются. |
| 3. Максимальное число | [level_3.py](part_3/level_3.py) | Проверка непустого набора неотрицательных целых чисел; комментарий к сравнению склеек. |

Треугольник существует, если сумма двух меньших сторон строго больше большей. После sorted достаточно проверить одно это неравенство и положительность меньшей стороны. Звёздочка в area(*map(...)) передаёт три числа отдельными аргументами. Формула Герона остаётся учебной; на почти вырожденных треугольниках возможна потеря точности float.

Короткие слова: порог строго меньше 5, дефисы и апострофы входят в длину. «из-за» и "don't" имеют длину 5 и не попадают в результат. У шаблона есть комментарий: [^\W\d_] исключает цифры и подчёркивание из символов слова, а повторяемая группа соединяет части через дефис или апостроф. В консоли используется input(): одна строка, затем Enter, без Ctrl+Z/Ctrl+D. Функция short_words принимает и многострочный текст. Обычный split оставил бы запятые и другие знаки рядом со словами.

Максимальное число: сравниваются left + right и right + left. Например, 9 нужно поставить перед 34, поскольку 934 больше 349. Выгодный обмен соседних частей увеличивает число, не меняя длину и остальные части. cmp_to_key позволяет использовать такое сравнение в sorted. Выражение (second > first) - (second < first) даёт 1, -1 или 0. Корректность дополнительно проверяется перебором всех перестановок небольших наборов.

## Часть 4. Регистрация и вход

[accounts.py](part_4/accounts.py) содержит три сценария: создание аккаунта, отказ при повторном логине и проверку входа.

- Хранилище по умолчанию: `~/.python_course_accounts`. На Windows это обычно `C:\Users\Windows\.python_course_accounts`.
- Для тестов предусмотрен необязательный параметр directory. Тесты работают только во временных каталогах, реальные аккаунты не изменяются.
- Логин содержит от 1 до 64 символов, без пробелов по краям. Регистр учитывается.
- Новый пароль содержит не менее 8 символов и не состоит из одних пробелов.
- Старые записи остаются читаемыми; новые требования проверяются при регистрации, чтобы не заблокировать вход в ранее созданный аккаунт.
- Пароль вводится через getpass и не выводится на экран обычного терминала.

PBKDF2 с 600 000 итераций усложняет перебор пароля. Соль представляет собой случайные данные, добавляемые при расчёте хеша; её можно хранить рядом с хешем. secrets создаёт соль. hmac.compare_digest сравнивает хеши без раннего выхода при первом различии. SHA-256 логина даёт безопасное имя каталога фиксированной длины; это не шифрование логина. Сам логин есть в JSON.

NamedTemporaryFile и replace защищают от публикации частично записанного JSON. Очистка временного файла теперь охватывает запись, закрытие и замену. Создание каталога логина резервирует его и предотвращает перезапись при конкурирующей регистрации. Если каталог уже существует без account.json, логин считается занятым; автоматическое удаление такого каталога не выполняется. Прерывание процесса или отключение питания может потребовать отдельной проверки такого каталога.

Отсутствующая запись, битый JSON, неверные поля или недоступный файл дают False при входе. И для существующего, и для отсутствующего/повреждённого аккаунта выполняется один расчёт PBKDF2 и сравнение. Это устраняет прежний мгновенный отказ. Тождественное время ответа не гарантируется: работа файловой системы различается. Тест проверяет одинаковое число дорогих операций, а не ненадёжное сравнение миллисекунд.

register возвращает True при успехе и False для занятого логина. Ошибки данных вызывают ValueError, ошибки хранения сохраняют тип OSError; консольная программа выводит понятное сообщение. Это учебный локальный пример, без сетевого сервера и ограничения числа попыток входа.

## Урок 3. Список покупок

[shopping_list.py](lesson_3/shopping_list.py) проверяет формат «название количество» и положительное конечное количество. После ошибочной строки можно продолжать ввод. rsplit(maxsplit=1) отделяет количество справа, поэтому названия с пробелами сохраняются.

Целые количества хранятся как int и выводятся без .0. Дробные поддерживаются; после сложения 0.5 и 1.5 получается целое 2. Прямые тесты функций дополнены консольными проверками. subprocess запускает отдельную программу, capture_output собирает вывод, text и encoding задают текст UTF-8, timeout предотвращает зависание теста. PYTHONIOENCODING задаёт UTF-8 для дочернего Python, а остальные переменные окружения сохраняются. Путь от __file__ не зависит от текущей рабочей папки.
